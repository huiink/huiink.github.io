# Fuwari 保守視覺微調設計

日期：2026-08-18

## 背景

網站已經使用 Astro 與 Fuwari，功能和維護流程正常。這次以
[PG72](https://pg72.tw/) 的整體一致感作為參考，但不複製其素材或改造成另一套版型。
目前最明顯的問題是文章封面在手機與文章頁佔比過大，尤其標誌類圖片會壓縮首屏文字；
部分一般頁面與側欄也需要統一間距和圖片比例。

使用者已在視覺比較中選擇「C：縮圖保留」，並要求整體不要偏離官方 Fuwari 太遠。

## 設計原則

- 保留官方 Fuwari 的導覽、橫幅、主欄／側欄、卡片和文章頁結構。
- 保留目前動畫橫幅、像素頭像、青藍色系與圓角語言。
- 只修正比例、間距、資訊層級和失效圖片狀態，不重新設計元件。
- 所有內容仍由既有 Markdown 或設定檔維護，不增加後續人員必須理解的新格式。
- 手機先顯示文章資訊，圖片作為辨識輔助；桌機維持 Fuwari 原本的側邊封面配置。

## 實作範圍

### 主題與導覽

- `themeColor.hue` 維持目前的 `210`。
- 將 `themeColor.fixed` 設為 `true`，讓整站顏色穩定並隱藏訪客換色控制。
- 導覽項目、圖示、搜尋、深色模式和行動版選單維持官方行為。
- 不更換字體、橫幅、頭像或導覽結構。

### 首頁文章卡

- 桌機版維持目前右側約 28% 的封面區域。
- 手機版不再將封面橫向鋪滿卡片，改為固定尺寸的右側縮圖。
- 縮圖容器尺寸穩定，不因圖片載入或標題長度造成卡片跳動。
- 標誌類封面完整顯示在淡色底上，圖片仍可點入文章。
- 標題、日期、分類、摘要、字數與閱讀時間沿用現有資料和順序。

### 文章頁封面

- 保留有 `image` 時顯示文章封面的官方行為。
- 限制封面在手機與桌機的高度，避免單張圖片佔滿首屏。
- 保留圓角與現有載入動畫；不加入新的輪播、燈箱或視差效果。
- 不新增 frontmatter 欄位，也不要求作者針對不同頁面準備多份圖片。

### 側欄與個人卡

- 保留個人卡、分類與標籤三個官方區塊及其順序。
- 固定頭像比例，避免透明或不同尺寸素材改變卡片高度。
- 微調文字行高、區塊間距和按鈕密度，使個人卡、分類與標籤在同一視覺節奏中。
- 社群連結、About 入口、分類計數與標籤網址完全不變。

### About、友鏈與歸檔

- About 內容繼續只編輯 `src/content/spec/about.md`。
- About 頁只調整手機內距、長表格的水平捲動和段落可讀性，不改寫內容結構。
- 友鏈繼續只編輯 `src/data/friends.md`，保留現有四欄格式與自動產生流程。
- 友鏈頭像統一為穩定方形；外部圖片失效時顯示名稱首字作為備援，不顯示破圖圖示。
- 歸檔頁只做與其他頁一致的手機內距和文字層級修正，年份與文章資料來源不變。

### 暫存文章

- 保留使用者已暫存的 `pre-exam-2026-Writeup.md` 內容與新版 description。
- 移除不屬於 Astro Markdown 的 `[TOC]` 標記。
- 將 `htmlembedded` 和 `python=` 程式碼圍欄恢復為 `html` 和 `python`，避免建置警告。
- 補回檔尾換行；文章圖片網址與正文不做其他改寫。

## 明確不做

- 不重寫 Fuwari 的頁面網格或建立新的主題層。
- 不複製 PG72 的橫幅、頭像、文案或個人資料。
- 不新增大型 Hero、裝飾背景、漸層、陰影特效或自訂動畫。
- 不改文章網址、日期邏輯、GitHub Actions、Giscus、RSS 或搜尋行為。
- 不改 Markdown、About 或 friends 的維護位置和資料格式。
- 不趁此次工作重構無關元件。

## 驗證

- `pnpm check` 與 `pnpm build` 成功，且沒有新增 Markdown 語言警告。
- 使用桌機與手機尺寸檢查首頁、文章、About、Archive 和 Friends。
- 手機文章縮圖不擠壓標題，不會超出卡片或造成首屏被圖片佔滿。
- 文章頁封面有固定上限，正文在合理捲動距離內出現。
- 深色模式、搜尋、行動選單、分類、標籤、友鏈和 Giscus 保持可用。
- 模擬失效友鏈頭像時顯示備援內容。
- 確認變更仍可辨識為官方 Fuwari，只呈現較一致的比例與細節。

## 完成與發布

視覺與功能驗證通過後，將設計變更和使用者暫存文章提交到 `main`，再推送至
`huiink/huiink.github.io`。GitHub Actions 應自動建置並部署，不使用額外 Token。
